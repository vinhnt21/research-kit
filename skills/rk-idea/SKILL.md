# Critique an idea

Turn a proposal into a question, rivals, one discriminating check, and a labeled judgment: pursue, reframe, defer, or reject. The judgment is a recommendation. It is not a validated result.

Literature search belongs to rk-survey. Locking a protocol belongs to rk-method. Data analysis belongs to rk-data. Manuscript drafting belongs to rk-write.

## Active paper

Resolve the paper from the request, the working directory, or that project's own instructions, such as an `AGENTS.md` beside the work. Read that paper's scientific notes before changing its files or stating its results. If several papers fit and the task would write, run, or make a paper-specific claim, ask which paper applies.

Leave sibling papers untouched. A sibling draft, bibliography, figure, codebase, or unpublished result is not a citation, a baseline, or reusable text. A shared read-only literature collection may be consulted after each source is checked for this paper. Put new files where this paper already stores that kind of artifact. Do not impose a directory layout, venue name, or tool.

## Working language

These instructions stay in English. The reply does not.

Write the chat reply, questions, and internal notes in the language the user is writing in. If this paper already keeps those notes in one language, continue in that language. If the request has no clear language, or the user's language and those notes disagree, ask which language to use before writing the note.

Write that language as an original note to a colleague. Do not translate these instructions sentence by sentence. Keep this skill's field names, and terms this paper already uses, as they already appear. In Vietnamese, use a short sentence a lab mate would say, and leave a research term in English when the Vietnamese word would be unclear or mean something else. For example, write "Số này lấy từ file vừa mở lại. Chưa kết luận nguyên nhân." Do not write "Bản ghi này bảo đảm tính liêm chính của đầu ra đã được mở lại."

A manuscript, a figure label, and a slide use the language of that artifact. If the task would write the artifact and that language is not already clear, ask before drafting it.

## Procedure

Work in order. Open only the reference for the step you are on.

### 1. Separate the problem from the proposal

State the problem or theoretical gap apart from the suggested fix. Name the system, the outcome, the operating regime, the comparison, and the decision the answer would change. Set one claim type: descriptive, associational, predictive, causal, mechanistic, or formal.

If the outcome of interest has already been inspected, mark the idea exploratory. Measuring whether the work can run — size, memory, time, iteration count, or convergence — is allowed. Record that measurement as a feasibility fact beside the question. It does not answer the scientific question.

### 2. State each candidate

Write every idea worth keeping as a candidate proposition with conditions, direction, and timeframe. Keep the mechanism in its own field. Map each construct to a measurement. Use a causal verb only after the estimand fields are filled.

Judge testability and claim language with [hypothesis quality](references/hypothesis-quality.md).

### 3. Record rivals and one discriminating check

List credible accounts that could produce the same appearance. Do not pad the list to a fixed count. For each candidate that might be pursued, record an observable consequence, the assumptions and the regime where they hold, the cheapest comparison, measurement, or proof obligation that separates it from a live rival, and a result that would weaken it.

Specify that check with [rivals and falsification](references/rivals-and-falsification.md).

### 4. Name only the recognition checks that change the judgment

When a bias, an evidence limit, or a fallacy would change pursue, reframe, defer, or reject, apply [biases and fallacies](references/biases-and-fallacies.md). Name the bias, the evidence limit, and the fallacy, in that order, then restate the claim. When none would change the judgment, say so in one line.

### 5. Assign the label

Apply [framing](references/framing.md) after the rivals and any recognition check are written. The label is pursue, reframe, defer, or reject.

### 6. Fill the record

Fill [hypothesis record](assets/hypothesis-record.md) and [rival matrix](assets/rival-matrix.md). If this paper already keeps idea notes, write the same fields there. Otherwise return the filled fields in the reply. Leave unknown fields empty. Novelty stays unverified until rk-survey has a bounded search for this paper. Do not run that search here. Saving the note does not require a commit.

### 7. Return

Return the question, the claim type, a provisional contribution, the novelty mark, the rival matrix, the discriminating check, the result that would weaken the candidate, and the judgment. If the judgment is defer, name the fact it waits on. Label the whole return as a judgment, not a validated result.
