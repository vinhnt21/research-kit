# Report gate

Use this before a progress note, result briefing, or talk states a number or a claim type. The order is fixed: regenerate the headline number, label the claim, list what is archived, then name the next verifiable step.

## Regenerate

A headline number may appear in the briefing only when it has just been produced again from the active paper.

- Re-run the paper's recorded procedure on its recorded inputs, or reopen the saved output that procedure names.
- Compare that value with the number you intend to state. If they differ, stop. Report the mismatch. Do not choose the more favorable figure.
- If the output cannot be reopened, leave the number out and say it is unverified.

Stop when the code, data, or protocol path is missing, when the only copy of the number is a memory or a draft sentence, or when the number comes from a sibling paper.

## Label the claim

Confirmatory means the result matches a freeze made before the outcome was seen. The freeze is a protocol record already stored with this paper. This gate does not create one and does not demand a particular audit program.

| What you find | Label |
| --- | --- |
| A freeze was written before this outcome was seen, and the question, procedure, and outcome definition match it | Confirmatory |
| No freeze exists | Exploratory |
| A freeze exists, but the sample, procedure, or outcome definition does not match it | Exploratory |
| The run departed from the frozen procedure | Exploratory, and name the departure |

Keep the exploratory label when a freeze does not exist. Do not backdate a freeze after the outcome is known. A side analysis chosen after seeing the outcome stays exploratory even if another claim in the same paper is confirmatory.

## List what is archived

Record local paths inside the active paper, and only those:

- Code that regenerates the headline number
- Data inputs that run used
- Environment description or lock the run used
- Protocol or freeze the label was judged against

Write the paths into the report record. A missing item stays missing; do not claim the result is archived. Do not upload the files. A sibling draft, figure, or codebase is not an archive entry.

## Next verifiable step

Name one next action a person can check, and the condition that counts as done.

- If regeneration failed, the next step is to recover that output. Do not write the briefing as if the number were known.
- If the label is exploratory because no freeze exists, the next step may be to freeze a new test on data not yet used. The current result stays exploratory.
- If the number regenerated and the label is set, the next step is the scientific follow-up the evidence actually supports, not a venue submission.

Then return to the skill procedure and write only from the filled record.
